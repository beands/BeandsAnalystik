# Skill: Карта стейкхолдеров и RACI

**Роль:** Product Owner
**Назначение:** построение карты стейкхолдеров (Power-Interest) и матрицы RACI.
**Имя файла:** `*_stakeholder-map.md`

## 1. Матрица влияние / интерес (Power-Interest Grid)

```
Высокое влияние / Высокий интерес   → Управлять внимательно (Manage Closely)
Высокое влияние / Низкий  интерес   → Удовлетворять     (Keep Satisfied)
Низкое  влияние / Высокий интерес   → Держать в курсе   (Keep Informed)
Низкое  влияние / Низкий  интерес   → Мониторить        (Monitor)
```

## 2. Формат карты стейкхолдеров

```markdown
| Стейкхолдер | Роль | Влияние | Интерес | Стратегия взаимодействия | Ключевые ожидания |
|---|---|---|---|---|---|
| CPO / спонсор | Спонсор | Высокое | Высокий | Manage Closely | ROI, соответствие стратегии |
| Служба безопасности | Согласующий | Высокое | Низкий | Keep Satisfied | Соответствие ИБ-стандартам |
| Конечные пользователи | Потребитель | Низкое | Высокий | Keep Informed | Удобство, скорость |
| Регулятор | Внешний | Высокое | Низкий | Keep Satisfied | Compliance |
```

## 3. Матрица RACI

- **R (Responsible)** — исполнитель, делает работу.
- **A (Accountable)** — ответственный за результат, **один на задачу**.
- **C (Consulted)** — консультирует до принятия решения.
- **I (Informed)** — информируется о результате.

```markdown
| Задача | PO | BA | System Analyst | Security | Dev Team |
|---|---|---|---|---|---|
| Приоритизация backlog | A/R | C | I | I | I |
| Сбор бизнес-требований | C | A/R | C | I | I |
| Техническая архитектура | I | C | A/R | C | C |
| Security review | I | I | C | A/R | I |
| Разработка фичи | I | C | C | I | A/R |
```

## 4. Правила построения

- На каждую задачу — **только один «A» (Accountable)**.
- Минимизируй количество «C» — избыточные согласования замедляют процесс.
- Обновляй карту стейкхолдеров при смене состава проекта или ключевых лиц.
- Если стейкхолдер не участвует в задаче — ячейка пустая с примечанием «не участвует»
  (не оставляй двусмысленных пустот).

## 5. Чек-лист качества

- [ ] Все ключевые стейкхолдеры идентифицированы (спонсоры, согласующие, пользователи, регуляторы).
- [ ] Для каждого указана стратегия взаимодействия.
- [ ] RACI: на каждую задачу ровно один Accountable.
- [ ] Нет пустых ячеек без явного обоснования (стейкхолдер не участвует).
- [ ] Матрица Power-Interest согласуется с RACI (высокое влияние → участие в ключевых решениях).
