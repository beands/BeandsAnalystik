# Skill: Приоритизация Backlog

**Роль:** Product Owner
**Назначение:** приоритизация backlog по RICE, WSJF, MoSCoW и матрице Value/Effort.
**Имя файла:** `*_backlog-priority.md`

## 1. RICE Score

```
RICE = (Reach × Impact × Confidence) / Effort
```

- **Reach** — сколько пользователей затронет за период (число/квартал).
- **Impact** — эффект на пользователя: `3` = массивный, `2` = высокий, `1` = средний,
  `0.5` = низкий, `0.25` = минимальный.
- **Confidence** — уверенность в оценке: `100%` / `80%` / `50%`.
- **Effort** — трудозатраты в человеко-месяцах.

Пример:
```
Фича: Быстрая оплата сохранённой картой
Reach:      12000 пользователей/квартал
Impact:     2 (высокий)
Confidence: 80%
Effort:     2 человеко-месяца
RICE = (12000 × 2 × 0.8) / 2 = 9600
```

## 2. WSJF (Weighted Shortest Job First, SAFe)

```
WSJF = Cost of Delay / Job Size
Cost of Delay = Business Value + Time Criticality + Risk Reduction
```

Каждый компонент оценивается по Fibonacci-шкале (`1, 2, 3, 5, 8, 13, 20`).

| Компонент | Вопрос для оценки |
|---|---|
| Business Value | Насколько это ценно для пользователя/бизнеса? |
| Time Criticality | Теряет ли ценность со временем? |
| Risk Reduction / Opportunity Enablement | Снижает риски или открывает возможности? |
| Job Size | Сколько усилий нужно для реализации? |

## 3. MoSCoW

- **Must have** — без этого релиз невозможен.
- **Should have** — важно, но есть обходной путь.
- **Could have** — желательно, если есть время/ресурсы.
- **Won't have (this time)** — сознательно откладываем.

## 4. Value vs Effort матрица

```
Высокая ценность / Низкие усилия   → делать первым   (Quick Wins)
Высокая ценность / Высокие усилия  → крупные проекты (Major Projects)
Низкая ценность  / Низкие усилия   → при наличии времени (Fill-ins)
Низкая ценность  / Высокие усилия  → не делать        (Time Sinks)
```

## 5. Формат результата приоритизации

```markdown
| # | Фича (US-*) | Reach | Impact | Confidence | Effort | RICE | MoSCoW |
|---|------|-------|--------|-----------|--------|------|--------|
| 1 | US-014 Быстрая оплата | 12000 | 2 | 80% | 2 | 9600 | Must |
| 2 | US-009 Программа лояльности | 8000 | 2 | 50% | 4 | 2000 | Should |
```

Дополнительно приложи WSJF-таблицу, если работаешь в SAFe-контексте.

## 6. Правила выбора метода

- **RICE** — когда есть данные по охвату аудитории (продуктовые фичи, growth-инициативы).
- **WSJF** — когда важна стоимость задержки и работа в SAFe / масштабируемом Agile.
- **MoSCoW** — быстрая приоритизация релиза без сложных расчётов.
- **Value/Effort** — визуальная приоритизация на воркшопах со стейкхолдерами.

Можно комбинировать: RICE для ранжирования + MoSCoW для отсечения релиза.
